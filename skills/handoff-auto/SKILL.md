# handoff-auto（読み込み → ゴール設定 → 自律実行）

現在の作業を新しい会話に引き継ぎます。新しい会話は引継書を読み込み、最適なゴールを自分で設定して自律的に実行します。次の手順だけを行い、追加の実装や調査はしないでください。

ユーザーの補足: $ARGUMENTS
（`$ARGUMENTS` がそのまま残っている場合は、このスキルを呼び出したときにユーザーが添えた文を補足とする。なければ無し。）

スクリプト `S` は `${CLAUDE_PLUGIN_ROOT}/scripts/hc-handoff.sh`。この `${CLAUDE_PLUGIN_ROOT}` が実際のパスに置き換わっていない場合は、この SKILL.md があるディレクトリから見て `../../scripts/hc-handoff.sh`。以下では絶対パスにして使う。

1. 引継書を書く。1 行目は `# 引継書: <作業の短い題名>`。必須項目:
   - ユーザーの依頼と完了条件
   - 完了したこと
   - 未完了のことと、**次の手順**（具体的なコマンド・ファイル・順番）
   - 重要な設計判断とその理由
   - ユーザーからの制約・禁止事項（メモリ・AGENTS.md・CLAUDE.md にあるものは参照だけでよい）
   - 変更したファイルと確認すべき位置（`path:line`）、ブランチ・未コミット状態
   - 実行したテストと結果、未検証の事項
   - 失敗した試みと、繰り返すべきでないこと
   - 起動中のプロセス・バックグラウンドのエージェント・外部の進行中作業（それぞれの目的・現在の状態・結果の確かめ方）
   - 次の会話が自分でゴールを決めるための材料: 候補となるゴールと優先順位、どこまで自律でやってよいか（push・マージ等の可否）

   確認済みの事実と推測は区別する。

2. シェルで 1 回だけ実行し、引継書を保存して再開ドライバを起動する。Codex・Muse Code ではシェルがサンドボックス内で動き `~/handoffs` への書き込みと hc の操作ができないので、最初から権限昇格（サンドボックス外）で実行する。Claude Code では通常どおり実行する。引継書の 1 行目（`# 引継書: ...`）と終端の `HANDOFF_EOF` は、下の例の字下げに関係なく**行頭から**書く:

   ```bash
   "<S の絶対パス>" start auto - <<'HANDOFF_EOF'
   # 引継書: ...
   ...
   HANDOFF_EOF
   ```

   出力の 1 行目が引継書のパス、2 行目が `launched` なら成功。`armed (no hc)` の場合は、ユーザーに「`/clear` すると引継書が読み込まれるので、続けて `引継書からゴールを設定して実行` と送ってください」と伝える。エラーなら原因を伝えて止まる。

3. 引継書のパスを 1 行で伝えて、すぐに応答を終える。その後ツールは呼ばない（応答の終了を待って、ドライバが `/clear` を送り、SessionStart フックが引継書を読み込み、ドライバが自律実行の指示を送る）。

4. バックグラウンドのエージェント・シェルが残っていても待たない（`/clear` 後も動き続ける）。
